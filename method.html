How we check

Each tool gets a row of evidence, not a score. The four things we separate are easy to mix up, so we keep them apart.

Four different things

Source inspectedWe read the README and repository details and hash the release files. Anyone can do this and it says little about whether the tool works.
Synthetic-file testingTests that run on files made to look like the real format. They catch bugs. They do not show a tool copes with a genuine file.
Native Windows testingA run on a real Windows machine. Wine runs and Linux runs do not count.
Genuine retail-file validationChecking against files from a retail copy. We have not done this for anything here, so every tool shows "No".

Who gets listed

There is no formula. Each tool is chosen by hand, looking at its licence, who is behind it, the quality of its source, what it actually does, which inputs it supports, what evidence exists and what its limits are. A project is not left out for being new. It is left out if we cannot say these things about it honestly. Our own two tools are listed, marked as experimental, with what has and has not been tested.

What we leave out

Anything that ships game files, keys or decrypted game content, anything that works around access controls, anything that runs or distributes game executables, and repositories with no source that point you at an installer. We do not link to any of those.

Release files

We download them, hash them, compare the hash with the one GitHub shows, and list what is inside. We never run a downloaded file.

Run it yourself

The crawler is crawler/crawl.py and the page builder is crawler/build.py. Both are plain Python 3.
